# v0.13.1 (2026-10-28) — 维护修复：发布链路、CI、Go 1.27 工具链、token 权限

> 项目停更两个月后的 P0 维护批次。代码本身健康（build/vet/race/staticcheck 全绿），
> 问题集中在"发不出版"和"文档/命令面与实现脱节"。

## 🚀 发布链路

- 补齐 v0.12.4–v0.13.1 缺失的 release：`scripts/release.sh` 重写 +
  新增 `scripts/publish-release.sh`，一键构建 5 平台、打包、生成 SHA256SUMS，
  并创建 Gitee release、上传资产（幂等，跳过已上传资产）
- 修复 `gitee release upload` / `release delete-asset` 一直 404 的根因：
  Gitee v5 附件路径是 `/attach_files` 而不是 GitHub 风格的 `/assets`
- 修复 `scripts/release.sh` 在自定义 `OUT_DIR`、macOS bash 3.2 下崩溃的问题
- 产物新增：每个归档包含 LICENSE；发布前对 host 二进制做版本 smoke check

## 🧰 CI 与质量门禁

- 从零补 CI：`.github/workflows/ci.yml`（GitHub Actions）+
  `.workflow/ci.yml`（Gitee Go）+ `scripts/ci.sh`
  （gofmt / go vet / golangci-lint / build / test -race / 交叉编译 / govulncheck）
- 全仓库 `gofmt -w`（140 个文件此前不符合格式）
- `govulncheck` 以 `go.mod` 的 `tool` 依赖固定版本，修复 `@latest`
  触发 go1.26 工具链降级、对 go 1.27 模块必失败的问题

## 🔐 安全与版本

- Go 1.25.0（已 EOL）→ 1.27.3：发布二进制消除 37 个标准库漏洞；
  `golang.org/x/net` v0.43.0 → v0.62.0、`x/sys` v0.42.0 → v0.49.0、testify v1.12.1
- `config.Load` 读取时自动把过宽的 `settings.json` 权限收紧到 0600
  （失败只告警不阻断，Windows 跳过 POSIX 位检查）
- 版本号收敛为单一来源：源码默认 0.13.1，新增测试锁定所有 README 徽章；
  移除 agent-help / exit-codes 里的硬编码版本号
- `--token` flag 帮助提示改用 `GITEE_TOKEN`（命令行 token 会出现在 `ps` / shell history）

## 📖 文档

- README 修正失效示例（`pr merge --delete-branch`、`auth login --with-token`）、
  `--limit` 默认值、真实环境变量清单与测试统计数字
- 新增 CI 徽章、发版流程说明

## 升级建议

```bash
# 下载对应平台归档并校验
sha256sum -c SHA256SUMS.txt
gitee version   # 应输出 0.13.1
```

Go 版本要求提升到 1.27.3+；从源码安装请使用同版本工具链。
